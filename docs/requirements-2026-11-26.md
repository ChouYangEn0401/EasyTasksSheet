## 0. 一句話

**整個系統只剩 Python**：裝機 `pip install`、啟動 `python main.py`，瀏覽器端是原生 JS（ES modules、零建置、不需要 Node.js）。
舊功能一個不少、舊資料直接沿用；在這個基礎上把工具做成「大家願意來用」的樣子。

## 1. 硬性要求（不可違反）

| # | 要求 | 怎麼驗 |
|---|---|---|
| H1 | 不需要 Node.js／npm：repo 裡沒有 `package.json`、`.ts`、`.tsx`、`.mjs`、Vite、eslint | `git ls-files | grep -E '\.(ts|tsx|mjs)$|package.*json|vite|eslint'` 無輸出 |

## 2. UI 改版（簡約、白底、乾淨，為了便利與可讀，不是改風格）

- U1 維持現有資訊架構（側欄、分頁、抽屜），不「模改」；調的是**間距、字級層次、對比、狀態色、空狀態、載入態**。
- U2 **阻擋鍊（任務相依）要一眼看懂**：我被誰擋、我擋著誰、整條鍊走到哪一步、誰逾期；在任務抽屜與清單列上都看得到，點了能跳過去。
- U3 搜尋：全站快速搜尋（Ctrl+K）找任務／專案／成員，結果可直接開。
- U4 視覺：清單列的狀態、負責人、期限、進度一列看完；看板卡片同樣資訊密度；甘特圖保留 11 月改版的樣子。
- U5 對話：任務討論區保留，提升可讀性（誰、何時、@ 提及明顯）。
- U6 AI：**這版不做**，但留彈性——設定頁預留「整合」區塊、後端留一個 `integrations` 設定點，不接任何模型。

## 3. 讓工具「幫人把事做完」（而不只是派壓力）

- R1 **本週任務一眼看到**：個人頁最上面就是「本週」（進行中、本週到期、本週完成），不用篩。
- R2 **工作日誌匯出**：照實驗室現行格式——`[專案] - 人名` → 條列每條任務 → 進度％與狀態字（完成／進行中／暫停），可複製貼進 Word／Google Docs（使用者提供的截圖為準）。
- R3 **週報模版**：至少三種——個人週報、PL 匯報（多人彙整）、設計決議；產出為可貼進投影片的結構（先做 HTML 版面＋可複製文字；PPT 檔另議）。參考使用者 skill 裡的 weekly／RD 模版。
- R4 每日 PPT 輔助：同 R2／R3 的資料，加「今日」範圍。
- R5 採用（adoption）策略另寫 `docs/adoption.md`：預設值替人決定、每週只要求一件事、週報模版就是誘因。

## 4. 參考 Monday／ClickUp 的優點（開源夠用就好）

- M1 搜尋與篩選：快速、可存常用篩選。
- M2 視覺：狀態色一致、進度條、人頭。
- M3 團隊對話：任務下的討論＋@。
- M4 彈性：自訂欄位（已有 properties）要好用。
- M5 AI：留接口不做。
