# 多台電腦同步（本機 → 中央）

每台電腦上的本機系統（另一套完整的 TasksSheets 資料庫）可以把資料**增量上傳**到中央伺服器。中央依「最後更新時間」合併；兩邊幾乎同時修改的資料不自動決定，交給管理者在網頁上確認。

> 原則：**資料不見不等於刪除**。同步只會新增與更新，系統絕不因為某台電腦缺少某筆資料就刪除中央的紀錄。

## 架構

```
本機 DB ──(sync-push：增量匯出、分批 HTTPS POST)──▶ 中央 /api/sync/push ──▶ 中央 DB
                                                      │
                                                      └─ 待確認衝突（sync_conflicts）──▶ 管理者在「資料同步」頁決定
```

- **單向**：只有本機 → 中央，不會把中央的資料寫回本機（不下行）。
- 本機與中央是同一套系統，資料以 `uid` 對應（migration `0005_uid`）；成員以**帳號**對應；GitHub 連動以專案名稱對應。
- 狀態與專案若 uid 對不到，會以「名稱完全相同且唯一」對應到中央既有的那一筆（例如兩邊各自安裝時產生的「待辦」「預設專案」），並記錄對照（`sync_uid_aliases`），之後的增量上傳沿用。
- 程式：中央邏輯 `server/app/sync_push.py`、API `server/app/features/sync_push.py`、本機命令 `server/sync_client.py`、前端 `src/web/features/admin/SyncPage.tsx`。資料表見 migration `0012_sync_push_sources_conflicts`。

## 使用步驟

1. 管理者在中央「資料同步 → 同步來源」按「新增同步來源」，為每台電腦建立一個來源（例如「小明的筆電」）。
2. 畫面會顯示**一次性金鑰**與完整命令，關閉後無法再查看（中央只存 SHA-256 雜湊）。遺失時「重新產生金鑰」，舊金鑰立即失效。
3. 在那台電腦的專案目錄執行：

   ```bash
   python -m server.cli sync-push --server https://中央網址 --token tss_xxx
   #  [--db 本機資料庫]  預設 DATABASE_PATH（data/app.db）
   #  [--dry-run]        只列出將上傳的筆數，不連線
   #  [--full]           忽略水位，全量上傳
   #  [--batch-size 500] 每批筆數
   #  [--machine-name 名稱] 預設主機名稱
   ```

   金鑰也可放在環境變數 `SYNC_TOKEN`（避免留在命令歷史）。可用工作排程器 / cron 定期執行。

4. 有衝突時，管理者到「資料同步 → 待確認衝突」處理。

## 增量水位（watermark）

- 本機以各表的 `updated_at` 判斷變動：只上傳 `updated_at ≥ 水位 − 60 秒` 的資料（多取 60 秒涵蓋匯出當下仍在寫入的資料，重複上傳為冪等）。
- 水位存在本機 `data/.sync-state.json`（與 `--db` 同目錄），以伺服器網址為鍵；值為該次匯出開始的時間。
- **只有全部批次都被伺服器確認成功後**水位才前進。任何一批失敗（網路中斷、金鑰錯誤…）水位不動，直接重跑即可。
- 沒有變動時仍會送出一個空批，讓中央更新「最後同步時間」。

## 套用規則（中央）

每一批在**單一 transaction** 內套用；任何錯誤全部回滾，該批不留下任何改動。

| 情況 | 結果 |
| --- | --- |
| 中央沒有這筆 | 新增（保留來源的 uid 與時間） |
| 兩邊內容相同（不計建立 / 更新時間與最後修改者） | 相同，不寫入、不寫變更流水 |
| 兩邊不同，更新時間差 **大於** `SYNC_AUTO_RESOLVE_MINUTES`（預設 10 分鐘） | 自動採較新者：上傳較新 → 更新中央；中央較新 → 保留中央（計為「中央較新而保留」） |
| 兩邊不同，更新時間差 **在門檻內** | **不套用**，寫入「待確認衝突」 |
| 本機沒有、中央有 | **不動**（缺少的資料絕不刪除） |
| 任務在本機被軟刪除（`deletedAt`） | 視為明確刪除，依上面的時間規則套用為**軟刪除**；其他類別沒有刪除標記，本機刪除的資料不會影響中央 |

- 衝突不阻擋同批其他資料。
- 相同來源 + 同一筆 + 同樣內容的待確認衝突不重複建立；同一筆又推送新版本時更新那筆衝突紀錄。
- 待確認衝突之後若被新上傳取代（內容變得相同，或時間差超過門檻自動決定），系統會把它標為已解決（處理者顯示「系統」）。
- 管理者已決定過的同一份內容（不計時間）再次上傳時不再詢問，尊重當時的決定。
- 需要參照的資料（例如任務的專案）在中央找不到時該筆略過，並在結果中列出原因。
- 每次寫入都記錄變更流水（`changes`，actor 為空，來源名稱記在同步摘要），線上使用者透過既有 SSE 即時看到更新。

### 成員

- 不上傳密碼雜湊、session、登入紀錄；成員只以帳號名稱與顯示名稱對應。
- 中央沒有的帳號（缺少成員）預設**略過指派**（負責人等欄位留空；個人清單因必須有擁有者而略過），並列在上傳結果中。
- 來源設定開啟「自動建立缺少的成員」時，才在中央建立為一般成員（隨機密碼、首次登入須改密碼）；需由管理者在成員管理「重設密碼」後才能登入。

### 衝突處理

- 清單顯示分類、標題、來源、雙方更新時間與「差 N 分鐘」。
- 並排比較「中央現有」與「來源上傳」，只列出內容不同的欄位；可逐欄位選擇，或一鍵「全部保留中央 / 全部採用上傳」。
- 決定方式：`keep_local`（保留中央，不改資料）、`use_incoming`（採用上傳）、`merged`（逐欄位合併，更新時間記為處理當下、最後修改者為處理的管理者）。單一 transaction，已解決的不可再處理。
- 可多選批次套用同一選擇（保留中央 / 採用上傳）。
- 「已處理紀錄」顯示誰在何時做了什麼決定。

## 自動備份

同一來源**每天第一次**上傳前，自動以 `VACUUM INTO` 備份中央資料庫到 `BACKUP_DIR`（檔名 `<db>-pre-sync-<來源>-<時間>.db`），每個來源保留 `BACKUP_KEEP`（預設 14）份。備份失敗時不寫入任何資料（500）。

## 權限

| capability | 內容 | 預設 |
| --- | --- | --- |
| `sync.manage` | 建立 / 停用 / 重新產生金鑰 / 刪除同步來源 | manager 以上 |
| `sync.resolve` | 處理待確認衝突、檢視處理紀錄 | manager 以上 |

兩者都不是受保護項目，root 可在「權限設定」調整。`POST /api/sync/push` 本身以金鑰驗證，不需要登入。

## 安全

- **需要 HTTPS**：金鑰在每次請求中傳送。`sync-push` 只接受 `https://`（`localhost` / `127.0.0.1` 例外供測試；`--allow-http` 可強制，不建議）。
- 金鑰 `tss_` + 32 bytes 隨機值；DB 只存 SHA-256 雜湊與末 4 碼（辨識用），以固定時間比對。
- 金鑰錯誤、來源停用 / 刪除、未帶金鑰一律回 **403**「同步金鑰無效或來源已停用」，不透露差異。
- 速率限制（單一行程、記憶體內）：同一 IP 15 分鐘內驗證失敗 20 次後一律 429；同一來源每分鐘最多 120 次請求。
- 上傳大小上限沿用 `DATA_IMPORT_MAX_MB`（預設 50 MB，超過 413）；單批最多 5,000 筆。
- 上傳內容以與匯入相同的嚴格 schema 驗證（多餘欄位、型別錯誤、超長字串皆拒絕）。

## 搬移、重送與冪等

- 同一份資料重複上傳不會產生任何變更（也不寫變更流水）；網路中斷後直接重跑。
- 換電腦或重建本機資料庫：在新電腦用同一個來源金鑰執行一次 `--full` 即可；已存在的資料會被判定為相同。
- 想重新上傳全部：`--full`（同樣冪等）。
- 刪除 `data/.sync-state.json` 等同下次改為全量上傳。

## 限制

- **附件檔案本體不同步**（只同步資料表中的業務資料；附件的檔案本體需另行搬移）。
- 單向上傳：中央的變更不會回寫到各台電腦。
- 更新時間比較依賴各台電腦的時鐘；時鐘誤差大的電腦可能被誤判為較新 / 較舊，建議開啟網路校時。
- 權限設定、成員密碼、session 不在同步範圍。
- 速率限制與覆寫快取為單一行程設計（與系統其他部分相同）。
