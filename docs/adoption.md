# 讓沒有正規訓練的團隊願意用：採用策略

> 📚 紀錄｜讀者：PL 與想推動團隊使用的人｜8 分鐘
> 建立：2026-11-26｜最後更新：2026-11-26
> 背景：使用者 2026-11-26 的課題——「一個沒有正規訓練的團隊與環境，如何慢慢培養專業的任務規劃能力」。這份是產品面的做法，不是程式規格；程式規格在 `requirements-2026-11-26.md` 第 3 節。

## 0. 一句話

**工具要先替人省事，人才會回來；習慣是省事的副產品，不是要求出來的。**

沒有受過專案管理訓練的人不會因為「這樣比較專業」而填任務；他們會因為「填了之後週報自動長出來」而填。所以每一個要求使用者做的動作，都要對應一個**當場**拿得到的回報。

## 1. 四個原則

| 原則 | 意思 | 在工具裡長什麼樣 |
|---|---|---|
| **一週只要求一件事** | 不要一次推「寫任務、估時、排期、標相依」。第一個月只要求「把本週在做的事寫進去」。 | 個人頁最上面就是「本週」；新增任務只有標題必填，其他全部有預設值。 |
| **回報要立即** | 填完馬上看到好處，不是月底才看到報表。 | 「匯報」一鍵產出工作日誌／週報，格式就是實驗室現在用的那份。 |
| **預設值替人決定** | 沒選專案就進「未分類」、沒選狀態就是「待辦」、沒填負責人就是自己。 | 快速新增（N 鍵）一行搞定；欄位能少就少。 |
| **看得見別人在做什麼，但不排名** | 總覽讓大家知道彼此在忙什麼、誰被卡住；不做排行榜、不算百分比。 | 總覽只有「近三週」與成員卡（`product-principles.md`）。 |

## 2. 分階段導入（每階段 2～4 週，做到了再進下一階段）

### 階段 A：先當待辦清單用
- 目標：每個人每週至少把「這週在做的 3 件事」寫進去。
- 只用：清單、個人頁「本週」、匯報（工作日誌）。
- PL 要做的事：**自己先用**，週會時直接開工具講，不另外做 PPT。大家看到 PL 的週報是工具產的，就會想「我也可以不用自己排版」。
- 不要做的事：不要求估時、不要求排期、不糾正狀態用法。

### 階段 B：開始標「卡在誰」
- 目標：被擋住的事講得出來。
- 加用：任務相依（「我被 X 擋著」）、延遲鏈頁。
- 誘因：週報自動多一段「目前被擋／我擋著誰」，PL 在週會上直接看那一段決定要不要介入。
- 這一步是培養「規劃」的起點：要標相依就得先想「這件事之前要先有什麼」。

### 階段 C：排期與看板
- 目標：有到期日、看板能用。
- 加用：甘特圖、看板拖曳、月曆。
- 誘因：甘特圖變成「下週要交什麼」的共同畫面；逾期用顏色講，不用人講。

### 階段 D：留下決定
- 目標：為什麼這樣做，三個月後查得到。
- 加用：任務討論區（@ 提及）、設計決議模版的週報、稽核紀錄。

## 3. 週報模版就是誘因（最重要的一條）

實驗室現在的工作日誌長這樣（使用者 2026-11-26 提供的截圖）：

```
[專案] - 人名
  ❖ 處理事項：
    ➢ 任務標題：進行中…(90%) – 備註
    ➢ 任務標題：暫停…(10%)
  1. 任務標題_完成
```

工具的「匯報」要能**一鍵**產出這個格式（以及個人週報、PL 匯報、設計決議三種模版），資料來源就是任務的專案、負責人、進度％、狀態、備註。
人只要在任務上改進度與狀態，週報就自己長出來——這就是「填任務」的回報。

## 4. 會讓人離開的事（反面清單）

- 必填欄位超過一個。
- 要先建專案、建狀態、設權限才能開始。
- 看到自己被排名或被算「完成率」。
- 介面一次出現所有功能（看板、甘特、相依、討論區全攤開）。
- 要裝東西、要讀說明書才能跑起來（所以 2.0 只剩 `python main.py`）。

## 5. 怎麼知道有沒有用

不看「任務數」，看三個行為：
1. 每週有幾個人**主動**更新了進度（不是 PL 催的）。
2. 週報是不是直接從工具匯出（PL 不用再自己整理）。
3. 週會上有沒有人用「我被 X 擋著」這種話——代表相依的概念進來了。

## 6. 從 Monday／ClickUp 學的、不學的

學：Ctrl+K 全站搜尋、狀態色一致、卡片上一眼看完（負責人頭像／期限／進度條）、任務下直接討論、自訂欄位。
不學：訂閱制的功能牆、自動化規則引擎（小團隊不需要）、AI 寫任務（這版不做，設定頁留位置）、儀表板堆滿圖表（總覽只放「近三週」）。
