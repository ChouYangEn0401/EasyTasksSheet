# 設計規格 — feat/admin-users（T7，輕量）

適用：`src/web/features/admin/**`，路由 `/admin/users`（需 `members.manage`，即 manager 以上；角色與權限見 `docs/permissions.md`）。token 與基礎元件一律引用 `core-shell.md`（下稱 core），本文件**不新增 token、不新增基礎元件**。

## 1. 版面

```
 [🔍 搜尋姓名或帳號…      ] [狀態：全部 ▾]                 共 8 位    [+ 新增成員]
 ┌─────────────────────────────────────────────────────────────────────────┐
 │ 成員                        角色        狀態                 更新        │
 │ (頭) 王小明  [你]           [超級管理員] ● 啟用              2 小時前  ⋯ │
 │      @wang                                                               │
 │ (頭) 李大華                 [成員]      ● 啟用  [待改密碼]   昨天      ⋯ │
 │ (頭) 陳怡君                 [成員]      ● 已鎖定             剛剛      ⋯ │
 │ (頭) 林志明（淡化）         [成員]      ● 已停用             11/02     ⋯ │
 └─────────────────────────────────────────────────────────────────────────┘
```

- 工具列高 48，控制項 `md`，間距 `--space-2`；搜尋框寬 240。表格為 surface 底、border、`--radius-lg` 的卡片（最大寬 960px 置左），列高 56（兩行），以 `--color-border-subtle` 分隔，hover 用 `--color-surface-hover`。
- 搜尋與狀態篩選為前端過濾（成員數少），寫入 URL：`?q=`、`?state=all|active|disabled`（預設 `all`）。
- 預設排序：啟用中在前、已停用在後；同組內角色高者優先（超級管理員 > 管理者 > 成員），再依顯示名稱。

## 2. 表格欄位

| 欄 | 內容 |
|---|---|
| 成員 | Avatar `md` + 顯示名稱 `--text-sm` 500；第二行 `@username` `--text-xs` text-tertiary。自己那列在名稱後加 `neutral` Badge「你」 |
| 角色 | Badge：超級管理員（root）`accent`、管理者（manager）`purple`、成員（user）`neutral` |
| 狀態 | 主狀態 Badge（帶色點）：啟用 `success`／已鎖定 `warning`／已停用 `neutral`。`must_change_password` 時另加 `neutral` Badge「待改密碼」；`in_overview = 0` 時另加 `neutral` Badge「不列入總覽」（Tooltip：不列入總覽統計，任務仍可指派給他） |
| 更新 | `<UpdatedAt at={updated_at}>` |
| 動作 | `⋯` ghost `iconOnly`，`aria-label="王小明 的操作"`，開啟 Menu |

- 已停用的列：名稱與帳號改用 `--color-text-tertiary`（不用整列降透明度）。
- 已鎖定 Badge 的 tooltip：「登入失敗次數過多，暫時無法登入」（有剩餘時間時補上「約 N 分鐘後自動解除」）。

### 動作選單（依列狀態顯示）

| 項目 | 顯示條件 | 行為 |
|---|---|---|
| 編輯 | 一律 | 開啟編輯 Dialog（§3.2） |
| 重設密碼 | 啟用中 | 確認 Dialog → 結果面板（§3.3） |
| 解除鎖定 | 已鎖定 | 立即執行，不需確認 |
| 停用 | 啟用中 | 確認 Dialog（§3.4），文字用 danger-text |
| 啟用 | 已停用 | 立即執行，不需確認 |

**最後一位 root 保護**：該列是唯一啟用中的超級管理員時，「停用」與編輯 Dialog 內的角色選項「管理者」「成員」為停用狀態，說明「至少需保留一位超級管理員」。後端仍回錯時，於頁面提示列顯示同一句文案。

**root 帳號**：登入者不是超級管理員（manager）時，root 列的選單只有停用狀態的「編輯」與說明「只有超級管理員可以管理此帳號」（後端同樣 403）。

## 3. 對話框

### 3.1 新增成員（Dialog `sm`，標題「新增成員」）

| 欄位 | 元件 | 規則與文案 |
|---|---|---|
| 帳號 | Input，`autocomplete="off"` | 必填；說明「登入用，建立後無法修改」；格式錯誤依 `src/shared/admin.ts` 的驗證訊息；重複時「此帳號已被使用」 |
| 顯示名稱 | Input | 必填；說明「顯示在任務與頭像上」 |
| 角色 | Select（超級管理員／管理者／成員） | 預設「成員」；manager 操作時「超級管理員」停用，說明「只有超級管理員可以指派超級管理員」 |
| 總覽 | Checkbox「列入總覽統計」 | 預設依角色：超級管理員關閉、其餘開啟（手動改過後不再隨角色變）；說明「關閉後，這個帳號不會出現在總覽的成員卡片與統計，適合只負責管理的帳號。任務仍可指派給他。」 |

- 表單下方 info-soft 提示列：「建立後會產生一組臨時密碼，成員首次登入時須自行變更。」
- 動作列：「取消」secondary、「建立」primary（必填未齊停用，送出中 loading）。欄位錯誤顯示在欄位下方；其他 API 錯誤顯示於表單上方 danger-soft 提示列。
- 成功後**同一個 Dialog 切換為結果面板**（§3.3），不關閉。
- 臨時密碼假設由後端產生並在回應中回傳一次。若後端改為由管理員輸入，則在表單加一個密碼欄（尾端「產生」ghost 鈕，預設已填入隨機 12 碼），結果面板不變。

### 3.2 編輯成員（Dialog `sm`，標題「編輯成員」）

- 欄位：帳號（readonly 樣式）、顯示名稱（Input）、角色（Select）、「列入總覽統計」（Checkbox，文案同 §3.1）。角色改為超級管理員時自動取消勾選（可再手動開啟）；改為非超級管理員不自動變更。API：`PATCH /api/admin/users/:id` 的 `inOverview`；操作 root 帳號仍需 `roles.assign_root`。「儲存」primary 僅在內容有變更時可按。
- 把自己降為成員時，儲存前多一次確認：「你將失去管理權限，並立即離開此頁面。」

### 3.3 臨時密碼結果面板（新增成員、重設密碼共用）

```
 ┌──────────────────────────────────────────┐
 │ 已建立成員「李大華」               [✕]   │
 │ 臨時密碼                                 │
 │ ┌──────────────────────────┬──────────┐ │
 │ │ k7Qm-2xRt-9vLp           │ [複製]   │ │
 │ └──────────────────────────┴──────────┘ │
 │ ⚠ 此密碼只會顯示這一次，請立即轉交本人。 │
 │                                  [完成]  │
 └──────────────────────────────────────────┘
```

- 密碼以 `--font-mono` `--text-lg` 顯示於 `--color-bg` 底、border、`--radius-md` 的方塊中，明文且可選取；右側 secondary 鈕「複製」，複製後文字換為「已複製」2 秒。
- 下方 warning-soft 提示列，文案如上。重設密碼時標題為「已重設「李大華」的密碼」，提示列後加一句「該成員下次登入時須設定新密碼。」
- 只有「完成」primary 與 ✕ 可關閉；**點遮罩與 Esc 不關閉**，避免尚未複製就消失。關閉後無法再次查看。
- 重設密碼的前置確認（Dialog `sm`）：標題「重設「李大華」的密碼？」，內文「會產生新的臨時密碼，原密碼立即失效。」，主要鈕 primary「重設密碼」。

### 3.4 停用確認（Dialog `sm`）

- 標題「停用「李大華」？」；內文「停用後無法登入，目前的登入狀態會立即失效。此成員的任務與紀錄都會保留，之後可重新啟用。」；主要鈕 `danger`「停用」。
- 停用自己時內文再加一行：「你將立即被登出。」

## 4. 回饋與狀態畫面

- 操作結果以**頁面提示列**呈現（工具列上方，core §5 提示列樣式，`role="status"`，4 秒後自動收起，可手動關閉）；本軌道不依賴 Toast（T9 才統一加入）。
- 成功文案（success-soft）：「已更新「李大華」」／「已解除「陳怡君」的登入鎖定」／「已停用「林志明」」／「已啟用「林志明」」。
- 失敗文案（danger-soft，不自動收起）：「無法完成操作：{後端訊息}」。
- 立即執行的動作（解除鎖定、啟用）執行期間，該列 `⋯` 換為 Spinner，完成後該列狀態 Badge 直接更新。
- 載入：5 列 Skeleton（Avatar 圓 + 兩行文字）。錯誤：ErrorState + 重試。
- 空狀態：至少有自己一位，不會全空；搜尋或篩選無結果時 EmptyState「沒有符合條件的成員」+「清除篩選」。
- **無權限**：一般成員直接輸入網址（或 API 回 403）時顯示 EmptyState，圖示鎖頭，標題「沒有權限」，說明「此頁面僅限管理者以上使用」，主要鈕「回到總覽」。側邊導覽入口已由 core 隱藏。

## 5. 互動與鍵盤

- `Tab` 順序：搜尋 → 狀態篩選 → 新增成員 → 各列的 `⋯`。`/` 聚焦搜尋框（focus 在輸入框時不觸發）。
- `⋯` 上按 `Enter` / `Space` 開啟選單；`↑` `↓` 移動、`Enter` 執行、`Esc` 關閉並把 focus 還給 `⋯`。表單內 `Enter` 送出該 Dialog 的主要動作。
- 新增成員 Dialog 開啟時 focus 在帳號欄；結果面板出現時 focus 移到「複製」鈕，並以 `aria-live="assertive"` 唸出「已建立成員，臨時密碼已顯示」（不唸出密碼內容）。
- 使用語意化 `<table>`；狀態與角色 Badge 以文字為可讀內容，色點 `aria-hidden`。選單內停用的項目保持可聚焦，讓鍵盤使用者讀得到原因 tooltip。

## 6. 響應式

- ≥ 1024px：如線框。
- 768–1023px：「更新」欄隱藏，改在成員欄第二行帳號之後以「·」接 `<UpdatedAt>`；搜尋框改為彈性寬度，「新增成員」維持在右；Dialog 寬 `min(400px, 100vw - 32px)`；表格不產生水平頁面捲軸。

## 7. 給實作者的檢查清單

1. 六項管理動作齊全：列出、新增、停用 / 啟用、重設密碼、調整角色、解除鎖定。
2. 臨時密碼只在結果面板出現一次，不寫入 URL、不進 query 快取、不出現在提示列或 log。
3. 最後一位超級管理員（root）的停用與降級在前端即被擋下並說明原因。
4. 每列都有 `<UpdatedAt>`；載入、無結果、錯誤、無權限四種畫面齊全；元件內無寫死色碼。
